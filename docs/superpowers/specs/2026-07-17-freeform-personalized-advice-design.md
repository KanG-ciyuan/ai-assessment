# 自由式个性化建议输出设计

## 背景

当前个性化建议要求模型返回三段固定 JSON，并分别满足字数范围。该设计虽然便于前端排版和校验，但会因为格式或个别字段长度不符合要求而丢弃本来有价值的回答，也让模型表达显得机械。

## 目标

- 让模型以自然中文直接回应测评结果，优先保证建议质量和完整性。
- 不要求 JSON、固定三段、固定标题、最低或最高字数。
- 不设置模型输出 token 上限，也不关闭模型的思考能力。
- 支持常用 Markdown 排版，让重点、列表和小标题在页面中正常阅读。

## 保留边界

- 每份已完成测评仍只能请求一次；同一匿名访客每天最多成功请求五次。
- 页面只渲染经过净化的 Markdown，禁止模型内容注入 HTML、脚本、链接协议等不安全内容。
- 空响应、接口异常和超限仍给出明确的用户提示，但不以“格式不合格”为失败条件。

## 后端设计

1. 请求向 DeepSeek Flash 发送测评摘要、四维分数、能力阶段和学习路径上下文。
2. Prompt 仅说明角色、事实边界和建议目标：结合结果指出最值得优先改进的方向，给出可执行建议；模型可自行组织篇幅与段落。
3. 移除 `response_format`、`thinking: disabled`、`max_tokens` 以及 JSON 字段校验逻辑。
4. 只验证响应内容为非空字符串，并返回原始文本；服务端继续在成功后写入 D1 用量记录。

## 前端设计

1. 将原有三个建议卡替换为一个完整建议阅读区。
2. 使用安全 Markdown 解析器，并关闭原始 HTML 解析；仅生成允许的文本结构。
3. 保存完整建议文本，刷新页面后仍可查看。
4. 失败提示继续放在同一模块内，不影响测评报告本身。

## 验收标准

- 模型返回任意正常自然语言或常用 Markdown 时，用户都能看到结果。
- `**重点**`、标题、列表、换行能以正常排版显示；HTML 和脚本不会执行。
- 模型输出不再因 JSON、字段数量、字数范围或 token 上限而被拒绝。
- 单份测评一次、同 IP 每日五次的成本护栏仍有效。
