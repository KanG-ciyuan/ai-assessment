# 匿名测评数据自动导出设计

## 目标

用户在起始页主动勾选同意后，网站在完成测评时自动将匿名结果写入飞书多维表格，用于验证题目、能力分布和产品使用情况。

## 用户同意与数据边界

- 起始页的“开始测评”按钮上方新增必选复选框：`我已知悉并同意：本次匿名测评数据将用于改进测评。`
- 未勾选时，按钮不可用；勾选后才能进入答题。
- 仅收集：随机测评编号、同意时间、完成时间、12 题答案、四维得分、总分、能力阶段和测评版本。
- 不收集：姓名、手机号、IP、设备信息、地理位置、个性化建议全文或用户自由文本。
- 不新增登录、画像追踪、营销触达或跨站追踪能力。

## 数据表设计

在现有 Base `AI 能力测评 V2.1 用户反馈` 中新增独立表 `匿名测评数据`，不与人工填写的 `体验反馈` 表混用。

字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| 测评编号 | 文本 | 网站生成的随机 `assessmentId`，用于去重，不对应真实身份 |
| 同意时间 | 日期时间 | 用户勾选同意的浏览器时间 |
| 完成时间 | 日期时间 | 完成 12 题并提交报告的时间 |
| 题目答案 | 文本 | 12 题答案的 JSON 字符串，仅用于题目分析 |
| AI 理解与判断 | 数字 | 0 到 9 分 |
| 任务表达与协作 | 数字 | 0 到 9 分 |
| 场景应用与问题解决 | 数字 | 0 到 9 分 |
| 工具选择与流程能力 | 数字 | 0 到 9 分 |
| 总分 | 数字 | 0 到 36 分 |
| 能力阶段 | 单选 | 固定规则生成的阶段名称 |
| 测评版本 | 文本 | 当前为 `V2.1` |

## 推荐架构

采用 Cloudflare Pages Function 直连飞书 Base。

1. 前端仅在用户勾选同意后允许开始，并把本次同意状态保留在本轮测评对象中。
2. 用户完成答题时，前端立刻展示本地固定规则报告；随后非阻塞地向 `/api/assessment-events` 发送 `assessmentId`、同意时间和答案。
3. Pages Function 校验同意状态、测评编号和完整答案，并在服务端使用现有规则重算四维分数、总分和阶段，忽略客户端提交的分数。
4. Function 通过飞书开放平台的服务端访问令牌，将整理后的记录写入 `匿名测评数据` 表。
5. D1 仅保存已成功投递的 `assessmentId` 和时间，用于去重；若飞书写入失败，删除本次投递标记，使用户下次正常完成一份新测评时仍可再次发送。

## 密钥与配置

以下配置只放在 Cloudflare Pages 的生产环境变量，不能提交到 GitHub，也不能放进前端：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- `FEISHU_BASE_TOKEN`
- `FEISHU_ASSESSMENT_TABLE_ID`

飞书自建应用需要具备向指定 Base 创建记录的服务端权限。现有用户授权只用于创建和管理表结构，不能直接暴露给网站访问者或放入网站代码。

## 失败与体验

- 飞书、网络或环境变量异常时，用户仍立即看到测评报告；页面不显示技术错误，也不阻断复测。
- 后端不接受缺少同意标记、无效测评编号或不完整答案的请求。
- 同一测评编号只允许成功写入一次，避免刷新、重复点击或网络重试造成重复记录。

## 验收标准

- 未勾选同意不能进入答题；勾选后可正常答题。
- 一份已同意的完整测评只在 `匿名测评数据` 表新增一条记录，字段与服务端重算结果一致。
- 缺少同意或缺少题目答案的请求被拒绝，且不会写飞书。
- 飞书写入失败时，测评报告仍正常展示。
- 飞书应用凭据、用户 IP 和个性化建议全文均不会出现在前端、Git 历史或 Base 记录中。
