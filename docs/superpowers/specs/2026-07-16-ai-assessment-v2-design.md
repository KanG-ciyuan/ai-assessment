# AI 能力测评 V2.0 设计方案

## 1. 目标与定位

V2.0 将产品从“了解多少 AI”的兴趣测评，升级为面向普通用户的 AI 应用能力测评。

核心问题是：用户能否把 AI 用进学习、生活和工作中的真实任务；如果暂时不能，下一步应从哪里开始。

产品保留一个统一入口，不按“零基础”与“进阶”拆分为两套题。用户完成后得到能力阶段、四维画像、优势、短板和可在七天内完成的行动建议。

### 本版本目标

- 让零基础用户也能看懂并完成测评。
- 区分“会聊天”与“会用 AI 解决问题”。
- 结果由固定规则生成，不依赖大模型，保证成本为零且结果稳定。
- 为后续的个性化陪练和知识库问答留下产品边界，但不在本版本实现。

### 非目标

- 不做登录、支付、课程、社群或账号体系。
- 不恢复 DeepSeek API 或 AI 深度报告。
- 不做两套题库或让用户先选择能力窗口。
- 不把飞书知识库直接暴露给网站用户。

## 2. 用户路径

1. 用户进入测评页，理解这是一个约三分钟的 AI 应用能力测评。
2. 用户完成 12 道题，每题选择最符合自己真实做法的一项。
3. 前端计算总分、四维分数和能力阶段。
4. 结果页显示阶段结论、能力画像、优势、优先短板和行动路径。
5. 浏览器保存最近一次结果；用户完成行动后可再次测评。

清除浏览器数据会清除本地记录。V2.0 不承诺跨设备历史数据。

## 3. 测评模型

### 3.1 四个能力维度

| 维度 | 定义 | 题数 | 满分 |
| --- | --- | ---: | ---: |
| AI 理解与判断 | 理解 AI 的适用边界，并能核验和修正输出 | 3 | 9 |
| 任务表达与协作 | 将模糊需求表达为清晰、可迭代的任务 | 3 | 9 |
| 场景应用与问题解决 | 用 AI 处理学习、生活或工作中的真实问题 | 3 | 9 |
| 工具选择与流程能力 | 根据任务选择工具，并组织多步骤工作过程 | 3 | 9 |

### 3.2 题目与场景分布

- 总题数：12 题。
- 每题：4 个选项，对应 0、1、2、3 分。
- 题目以真实情境选择为主，少量题目可检验稳定使用习惯。
- 生活场景 4 题、学习场景 3 题、工作场景 5 题。

题干不考工具名、提示词术语或编程能力。即使当前没有工作，用户也可以根据学习和生活经验作答。

### 3.3 能力阶段

| 总分 | 阶段 | 含义 |
| ---: | --- | --- |
| 0-9 | 认知起步 | 知道 AI 能做什么，但还未形成稳定使用习惯 |
| 10-18 | 基础协作 | 能用 AI 完成简单任务，但表达和结果判断仍不稳定 |
| 19-27 | 场景应用 | 能将 AI 用进学习、生活或工作中的具体问题 |
| 28-36 | 流程进阶 | 能选择工具、拆解任务并组织更复杂的工作流程 |

短板约束：任一维度低于 4 分时，最终阶段最高为“场景应用”。这防止用户因其他维度得分较高，却在关键能力上存在明显缺口时被判为最高阶段。

## 4. 结果页规则

结果页必须由总分、各维分数和固定内容模板生成，不调用模型。

### 4.1 页面结构

1. 阶段结论：阶段名称与一段不超过两句的解释。
2. 四维画像：雷达图、四维分数和每维一句解释。
3. 优势：取最高的 1-2 个维度，说明对应的真实能力。
4. 优先短板：取最低维度，说明当前限制和改进方向。
5. 行动路径：给出三项可在七天内完成的具体动作。
6. 复测入口：说明本次记录保存在浏览器本地，建议完成行动后复测。

### 4.2 行动路径类型

| 适用情况 | 行动路径 |
| --- | --- |
| AI 理解与判断或任务表达较弱 | 基础上手路径：为一个高频任务建立提示词模板，并练习补充目标、背景和输出格式 |
| 场景应用较弱 | 场景应用路径：选择一个真实任务，完整完成目标、输入、核验和修改四步 |
| 工具选择与流程能力较弱，且总分较高 | 流程进阶路径：将一个重复任务拆成步骤，整理为可复用模板或简单工作流 |

如果两个维度同分为最低，优先选择“AI 理解与判断”，其次是“任务表达与协作”，以保证结果先解决可靠性与表达问题。

## 5. 技术边界

### 本版本

- 继续使用现有静态前端与 Cloudflare Pages 部署方式。
- 在前端维护题库、计分、阶段判定、模板化报告和本地记录。
- DeepSeek API 保持关闭；不向 D1 写入测评数据也可以完整使用核心体验。
- 需要为题库数据、计分、阶段边界、短板约束和报告模板补充自动化测试。

### 后续候选版本：知识库陪练

飞书知识库不纳入 V2.0。若验证用户需求并确定商业化方向，可单独规划“AI 应用陪练”。

候选架构是：飞书知识库经授权后由服务端同步，清洗后的可授权内容被切分并建立向量索引；用户提问时只检索少量相关片段，再由大模型生成回答。前端不保存飞书凭证、原始文档 URL、付费来源或完整知识库文本。

该能力的收费价值应是“基于测评短板的持续陪练与任务方案”，而不是通用聊天问答。任何来自付费资料或第三方内容的文本都必须先确认可对外使用，并优先转化为原创总结、模板和案例。

## 6. 验收标准

- 12 道题均有 4 个选项，且每题明确映射到一个维度和 0-3 分。
- 任意答案组合均能生成有效总分、四维分数、阶段和行动路径。
- 阶段阈值和“任一维低于 4 分”的短板约束有自动化测试。
- 未配置 API Key 或 API 不可用时，测评与结果页仍能完整运行且不显示误导性 AI 分析。
- 最近一次结果可在同一浏览器中恢复；清除浏览器数据后的表现有明确提示。
- 上线后邀请至少 10 位不同基础的真实用户体验，两周内收集并记录问题，再决定 V2.1 范围。

## 7. 版本路线

- V2.0：完成题库、固定计分、模板化结果页和本地复测体验。
- V2.1：根据真实反馈优化题目措辞、结果可读性和行动路径，不提前承诺新功能。
- V2.2：在验证付费需求后，单独设计并实现受控的知识库陪练能力。
